# 궁합 리딩 템플릿 (소스 분리 원칙)

궁합 답변은 세 소스를 섞지 않고 나란히 제시한다:

1. 각자의 로컬 계산 특성 (`saju.mjs`, 사람당 1회 실행)
2. 신한라이프 B017 궁합 점수·본문 (제공자 결과, 라벨 필수)
3. 별자리 시나스트리 (`natal.mjs --synastry`, 요청 시)

## 1. 각자의 명식 (로컬 계산)

두 사람 각각에 대해 `saju.mjs`를 한 번씩 실행한다:

```bash
node skills/saju/scripts/saju.mjs --input <person1-request.json>
node skills/saju/scripts/saju.mjs --input <person2-request.json>
```

각 결과에서 궁합에 쓸 수 있는 것은 그 사람 자신의 계산값뿐이다:
일간(`natal.dayMaster`), 오행 분포(`counts`), 십신, 합충형파해
(`relations[]`, 각자 명식 내부의 것), 공망·원진·귀문(`specialRules[]`).

**두 명식 사이의 합충형파해는 계산되지 않는다.** 이 CLI에는 두 사람을
비교하는 엔드포인트가 없고, 한 사람의 기둥과 다른 사람의 기둥을 맞춰보는
교차 합충은 LLM이 직접 계산할 수 없다. 사용자가 "두 사주의 합"을 물으면
그 항목은 "계산되지 않음(uncomputed)"으로 표기하고, 각자의 명식 특성과
제공자 점수로 답한다. 추측으로 교차 관계를 만들지 않는다.

## 2. 제공자 궁합 (B017)

SKILL.md 섹션 4의 curl 레시피로 B017을 호출한다. 응답의 연인/결혼/친구/
직장 궁합 점수와 본문은 **신한라이프 제공자 결과**로 라벨을 붙여 전한다.
로컬 계산값과 섞어 한 점수처럼 보이게 하지 않는다.

## 3. 별자리 시나스트리 (선택)

```bash
cd <skill>/scripts && node natal.mjs --synastry '{"person1":{...},"person2":{...}}'
```

score 0~100과 교차 어스펙트는 **점성술 결과**로 라벨을 붙인다.

## 4. 답변 구성

- 사람별 특성: 각자의 `saju.mjs` 결과에서 일간·오행 분포·눈에 띄는 관계를
  요약한다. 근거 필드를 덧붙인다(예: `natal.candidates[0].pillars.day`).
- 함께 보기: "두 분의 오행 분포가 서로 다른 축에 치우쳐 있다"처럼 각자의
  계산값을 나란히 비교하는 서술은 가능하다. 단, 두 차트의 글자를 직접
  합·충 판정하는 것은 uncomputed 항목이다.
- 제공자 점수: B017 %를 그대로 인용하고 출처를 밝힌다.
- 시나스트리 점수: 역시 별도 출처로 표기한다.
- 어느 한 소스를 정답으로 단정하지 않는다. "경향과 포인트"로 전하고
  `references/safety.md`의 면책 한 줄로 마무리한다.
- 한쪽의 생시를 모르면 그 사람의 시주·시간 관련 해석은 빼고
  `UNKNOWN_BIRTH_TIME` 한계를 명시한다.
